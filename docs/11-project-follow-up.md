## Fixed along the way

- **Docker `tmpfs` uid/gid mismatch (found in production use).** The
  session directory's `tmpfs` mount (`SRXWEB_SESSION_DIR`,
  `/tmp/srxweb_sessions`) had no `uid`/`gid`, so it defaulted to
  `root:root` with `mode=1700` (owner-only) — the `nonroot` user
  (uid 65532 in `gcr.io/distroless/static-debian12:nonroot`) was locked
  out of its own session directory: unreadable/unwritable at runtime.
  Fixed in `docker-compose.yml` and in the manual `docker run` fallback
  in `docs/RUNBOOK.md` (section 3.0.c) by adding `uid=65532,gid=65532`
  to the `tmpfs` mount options. Also documented as a troubleshooting
  entry in `docs/RUNBOOK.md` section 3.5.
- Several `internal/config` files (`ipaddr.go`, `extract_text.go`,
  `fuzz_test.go`, `node_test.go`, `addressbook_test.go`) still had
  French comments/test data left over from backlog item 3's translation
  pass — written without accented characters, so invisible to a plain
  accented-character grep. Found during the item 5 audit and fixed. See
  "Outstanding" below for the process gap this exposed.

## Outstanding from the security/architecture audit (item 5)

Manual review only — `govulncheck`/`gosec` couldn't run in the sandbox
(no access to `proxy.golang.org`, see `docs/08-tests-ci.md`). None of
these are blockers for internal use; they matter more the further the
deployment moves from "single trusted user on localhost."

- [ ] **`SRXWEB_HOST` defaults to `0.0.0.0`.** Fine inside Docker (the
  real boundary is the compose port mapping), but running the binary
  directly on a shared host without reading the docs silently exposes
  the service to the whole LAN. Consider defaulting to `127.0.0.1` and
  requiring an explicit opt-in for wider exposure.
- [ ] **`rateLimiter.buckets` (`internal/api/middleware.go`) never
  evicts entries.** One entry per source IP ever seen, never cleaned up
  — a slow memory leak on a long-running deployment seeing many distinct
  IPs (e.g. behind a proxy). Same fix shape as
  `session.Manager.maybeSweep`: a TTL + lazy sweep.
- [ ] **Session sweep only runs on `Manager.Create()`.** If the service
  sits idle with no new analysis, expired session directories are never
  cleaned up. Documented as "best effort"; a real periodic ticker would
  be more robust for a long-running server deployment.
- [ ] **CLI output files written `0o644`** (`cmd/srxtool/main.go`),
  world-readable, even though they can contain a rename plan or a
  firewall conf. `internal/session` uses `0o700` for session
  directories — the same rigor could apply to `0o600` on the CLI side.
- [ ] **Docker base images not pinned by digest**
  (`golang:1.22-alpine`, `distroless/static-debian12:nonroot` by tag
  only). Fine for now, `@sha256:...` would be stricter for supply-chain
  reproducibility.
- [ ] **`govulncheck`/`gosec` never actually run.** Sandbox network
  limitation, not a code issue — but genuinely unverified until the
  first CI run on a real push. Don't treat as "checked."
- [ ] **Process gap**: the leftover-French files found above slipped
  through because the earlier translation sweep only grepped for
  accented characters, and some French text had been typed without
  accents. Worth adding a CI check (or just a habit) that greps for a
  short list of common French words as a second pass, not just
  diacritics, whenever a "full translation" task is claimed done.

## Architecture notes (non-blocking, from the same audit)

- `internal/api/handlers.go` is getting dense (~480 lines, 5 handlers).
  Fine today; if a 6th tool is added, consider splitting by file
  (`handlers_analyze.go`, `handlers_rules.go`, ...).
- No cancellation context propagated through long operations (XLSX
  generation, parsing a large conf) — a client that disconnects doesn't
  free the in-flight server work. Minor for a single-user internal tool;
  first thing to add if usage becomes multi-user.
- `cmd/srxtool/main.go`'s `reorderArgs` is a hand-rolled workaround for
  a stdlib `flag` limitation. Works, is tested, probably not worth a
  `cobra`/`pflag` dependency for this alone — reconsider if the CLI
  grows further.
